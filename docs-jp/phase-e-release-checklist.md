## 0. この文書について

**配布物の仕様であって、コードを触るときの前提ではない。**
だから仕様書 (v0.8) には入れず、独立させてある。

仕様書は「このコードをどう触るか」を持つ。こちらは「**使う人に何を渡すか**」を持つ。
Phase E に着手するとき、手順書を書く前にこの一覧を上から順に潰す。

> **⚠️ Phase E には Phase B (UI フォントの焼き込み) が必須である。**
> フォントを焼き込まないと「SD にフォントを置かないと日本語が出ない」という
> 制約が残り、`.bin` のみの配布が成立しない (仕様書 §5.3 / §7.4)。

## 1. 手順書に必ず含めるべき事項 (11項目)

| # | 項目 | なぜ要るか |
|---|---|---|
| 1 | **ロック判定の方法** — Chrome / Edge で xteink.dve.al を開き、ポートが出るかを見る | ロック品かどうかで案内が変わる。読者は自分の端末がどちらか知らない |
| 2 | **ロック品でも SDカード経由で書き込める**こと | ここを書かないと「USB が使えないから無理」で諦める |
| 3 | **世代を跨ぐ更新には Escape Hatch が必要**なこと | **最重要。**1.4系の SD 更新機能は 1.5系イメージを「Invalid firmware file」で拒否する。これを知らないと詰む (仕様書 §2.5) |
| 4 | **初回起動時にキャッシュ再生成で時間がかかる**こと | develop ベースのため。実測2〜3秒だが、知らないと「壊れた」と思う |
| 5 | 本文フォントの導入方法。**任意であること、無くても UI は日本語**であること | Phase B の成果そのもの。ここを曖昧にすると価値が伝わらない |
| 6 | **復旧用ファームの事前確保** | 書き込む前に退路を用意させる。一覧は仕様書 §2.5 |
| 7 | **SDルートに `update.bin` を常設しない**運用ルール | 誤爆防止。毎回の起動で更新が走る事故を避ける |
| 8 | **Error 9 は文鎮化ではない**こと | 既知の未解決バグ。再起動して再試行すればよい。これを書かないと「壊した」と思わせる |
| 9 | **1.2.0 系を導入しない**こと | ロック品 X4 で OTA が常に失敗する既知事例がある (RAM不足による TLS+書き込みの競合)。**更新手段を失う** |
| 10 | **コマンドはコピペ可能な形で記載** | GitHub ユーザー名の `I` と `l` の取り違え等が実際に起きる |
| 11 | **SDカードは MLC 品を推奨** | 前カードは書き込み過多で物理故障した。フォーマットも不能になる |

---

## 2. 配布物

1. `update.bin` (日本語UI版)
2. 導入手順書 (**日本語主体**)
3. 推奨する本文用フォントの案内

**UI フォントを焼き込むため、フォント一式の同梱は必須ではない。**本文フォントは任意。

---

## 3. 想定読者

- AliExpress 等でロック品 X4 を購入した日本語話者
- **日本語表示を必要とするが、ファームウェア開発の経験がない層**

**後者を想定読者に含めることが、上の11項目すべての理由である。**
「分かっている人には不要な注意」を省くと、分かっていない人が詰む。

## 4. ライセンス

MIT (上流を継承)。**動作保証を行わない旨を明記する。**

> **⚠️ 焼き込むフォントのライセンスを確認すること。**
> OFL の Modified Version には「フォーマットの変更、あるいは新しい環境への移植」が
> 含まれる。TTF → `.cpfont` の変換はこれに該当し、**ファームウェアバイナリに
> フォントデータが入るなら「再配布」である。**
>
> - ライセンス表示の同梱が必要
> - **RFN (Reserved Font Name) のあるフォントは改名が必要**
>   (UDEV Gothic は RFN あり。派生元の BIZ UDゴシック / JetBrains Mono 分の
>   著作権表示も要る)
>
> 詳細は仕様書 附録C。**Phase B でフォントを選ぶ時点で確認する。**
