**作成日**: 2026-08-10
**位置づけ**: `docs-jp/xteink-x4-jp-firmware-spec-v0_5.md` §6 の機能要件 F-8 の詳細設計

## 0. なぜやるのか

**日本語の著作権切れ文学は、事実上すべて青空文庫にある。**

青空文庫のテキストは独自のプレーンテキスト記法を持ち、**ルビが `漢字《かんじ》`
という形で本文中に直接書かれている**。したがって EPUB に変換しなくても、
TXT リーダーが `《》` を解釈できれば、**青空文庫のファイルをそのまま
ルビ付きで読める**。

これに対応した日本語リーダーは、それだけで存在価値がある。
上流には通らない機能だが (SCOPE.md の対象外)、フォークなら制約はない。

### 上流との関係

| 項目 | 判断 |
|---|---|
| 上流に出すか | **出さない。**日本語固有の記法であり、`SCOPE.md` の対象外 |
| 上流の変更を待つか | 待たない |
| ただし | ルビ描画の基盤に手を入れる場合、上流の EPUB 実装と衝突しないよう配慮する |

---

## 1. 青空文庫記法の全体像

### 1-1. 実測 (石原莞爾『最終戦争論』/ 112,650 B / Shift-JIS)

| 記法 | 出現数 | 例 |
|---|---|---|
| ルビ `《》` | 47 | `真面目《しんめんぼく》` |
| ルビ範囲指定 `｜` | 5 | `包囲｜殲滅《せんめつ》` |
| 注記 `［＃...］` | 77 | `［＃１字下げ］` |
| 外字 `※［＃...］` | 2 | `※［＃「衄のへん＋絆のつくり」、U+8845、62-12］` |

注記の内訳:

| 種類 | 数 | 対応の要否 |
|---|---|---|
| `［＃N字下げ］` | 29 | 見た目に影響。**対応が望ましい** |
| `［＃「...」は大/中/小見出し］` | 15 | **見出しとして扱えると良い** |
| `［＃ここから/ここで...］` | 6 | 範囲指定。字下げ・字詰め |
| 外字 | 2 | U+xxxx が読めれば実文字に |
| その他 (図の位置等) | 25 | **除去のみでよい** |

### 1-2. 記法の正確な仕様

#### ルビの親文字の決定規則

`｜` がある場合はその位置から `《` までが親文字。
無い場合は、**`《` の直前から遡って、同種の文字が続く範囲**が親文字になる。

同種の判定は以下の順:

1. 漢字 (`\u4e00-\u9fff` + `々〆ヶ`)
2. カタカナ
3. 英数字
4. ひらがな

> **`｜` が必要になるのは、親文字を自動判定できない場合。**
> 例: `包囲｜殲滅《せんめつ》` — `｜` が無いと「包囲殲滅」全体が
> 親文字になってしまう。

#### ファイル構造

```
1行目: 作品名
2行目: 著者名
（空行）
-------------------------------------------------------
【テキスト中に現れる記号について】
（凡例）
-------------------------------------------------------

（本文）

底本：「...」
（奥付）
```

**凡例ヘッダと底本フッタは本文ではない。**表示するなら除去すべき。

## 2. 【最重要】未確認の前提

**本機能の実現可能性は、以下の1点にかかっている。**

### 2-1. TXT リーダーはルビを描画できるのか

| 事実 | 出典 |
|---|---|
| TXT / EPUB / XTC は**完全に別クラス** | spec §6.2 |
| TXT は**視覚行1本につき `drawText` 1回**の行単位描画 | spec §6.2 (実測 約75回) |
| EPUB は `Page::render()` が単語・ラン単位で描く (約2,900回) | 同上 |
| ruby は `#2665` で EPUB に実装された。`TextBlock` がルビを保持 | spec 附録E |

**つまり、ルビの実装は `TextBlock` / `Page::render()` 側にある可能性が高く、
TXT リーダーからは使えないおそれがある。**

その場合、TXT にルビを出すには**描画層に新規実装が要る**。
これは「既存機能の再利用」ではなく「新機能の開発」であり、
工数の桁が変わる。

**調査 (§4) で最初に潰すべき前提。**

### 2-2. ルビが折り返しと行高に与える影響

ルビを出すと、以下が連鎖する。

| 影響 | 内容 |
|---|---|
| **行高** | ルビの分だけ行が高くなる。1ページの行数が減る |
| **折り返し幅** | **ルビが親文字より幅広の場合、その分を考慮しないと重なる** |
| **ページ分割** | 行高が可変になると `buildPageIndex()` の計算が変わる |
| **F-7 との干渉** | 折り返しが O(n²) の状態でルビ幅の計算を足すと、さらに遅くなる |

**F-7 (折り返しの O(n²) 修正) を先に済ませておく方が安全。**

### 2-3. Shift-JIS が読めないと何も始まらない

**青空文庫のテキストは Shift-JIS。**
F-3 (文字コード自動判別) が未実装のいまは、そもそも文字化けして読めない。

**F-3 は F-8 の絶対的な前提条件。**

## 3. 実装の段階分け

依存関係を踏まえた順序。

### 前提: F-3 (文字コード自動判別)

**これが無いと青空文庫のファイルが読めない。**先に実装する。

### 段階1: 記法の除去 (最小)

**ルビを出さない。記法を消して読めるようにするだけ。**

| 対象 | 処理 |
|---|---|
| `《よみ》` | **除去** (親文字は残す) |
| `｜` | 除去 |
| `［＃...］` | 除去 |
| `※［＃...U+xxxx...］` | U+xxxx を実文字に。読めなければ `〓` |
| 凡例ヘッダ / 底本フッタ | 除去 |

**これだけでも実用価値がある。**いまは `《しんめんぼく》` が本文中に
そのまま表示されて読みにくい。

**難易度: 低。**文字列処理のみで、描画層に触れない。

### 段階2: ルビの描画

**§2-1 の調査結果次第で難易度が激変する。**

| 前提 | 難易度 | 内容 |
|---|---|---|
| TXT から既存のルビ基盤が使える | 中 | パース結果を渡すだけ |
| 使えない | **高** | 描画層に新規実装。行高・折り返しの改修を伴う |

必要な要素:

1. 行の解析時に、ルビの位置 (親文字の開始/終了、読み) を保持する
2. 折り返し計算にルビ幅を加味する
3. 行高をルビの有無で可変にする
4. 親文字の上にルビを描画する (小さいフォントサイズ)
5. ページ分割が行高の変化に追従する

**ルビ用のフォントサイズ**: 本文の約半分。8pt 前後になる見込み。
本文フォント (SD) に 8pt が必要になる可能性がある。**要検証。**

### 段階3: 注記への対応 (任意)

| 記法 | 対応案 |
|---|---|
| `［＃「...」は大/中/小見出し］` | 見出しとして扱う (太字・サイズ変更・目次生成) |
| `［＃N字下げ］` | 行頭にインデント |
| `［＃ここから/ここで...］` | 範囲指定の字下げ・字詰め |
| 傍点 | 圏点の描画。**難易度高。後回し** |

**段階3 は無くても実用になる。**優先度は低い。

## 4. 調査項目 (着手前に必ず実施)

### 4-1. ルビ基盤の所在と再利用可能性 — **最優先**

| # | 調べること |
|---|---|
| 1 | `#2665` (`d0359edf`) の変更ファイル一覧。ルビの実装がどの層にあるか |
| 2 | `TextBlock` がルビをどう保持しているか (データ構造) |
| 3 | ルビの描画を実際に行っているのはどのクラス・どの関数か |
| 4 | **`TxtReaderActivity` からその経路に到達できるか** |
| 5 | `TxtReaderActivity` の描画が `GfxRenderer::drawText` を直接呼んでいるか、間に層があるか |
| 6 | 行高がどこで決まっているか。可変にできるか |
| 7 | `buildPageIndex()` が行高をどう扱っているか |

**この結果次第で段階2の難易度が決まる。**
再利用できない場合は、工数の見積もりをやり直す。

### 4-2. フォントサイズの制約

| # | 調べること |
|---|---|
| 1 | ルビ用に本文より小さいサイズを使う場合、どのフォントが引かれるか |
| 2 | SD フォントに該当サイズが無い場合の挙動 |
| 3 | UI サブセット (Phase B で焼き込むもの) をルビに流用できるか |

> **注意**: UI サブセットには本文で使う漢字が入っていない。
> ルビは主にひらがな・カタカナなので流用できる可能性はあるが、
> 「彼《かれ》」のような読みは平仮名でも、**漢字の読みに漢字が来る例外**
> (`難《がた》い` 等はひらがな) を確認する必要がある。

### 4-3. 実データの調査

| # | 調べること |
|---|---|
| 1 | 青空文庫の複数作品で、記法の出現パターンを確認 |
| 2 | ルビが親文字より幅広になる頻度 |
| 3 | 1行あたりのルビ数の最大値 |
| 4 | 外字の出現頻度と、U+xxxx が無い形式の有無 |

## 5. 代替案 (Plan B)

**段階2 が現実的でないと判明した場合の逃げ道。**

### PC 側で EPUB に変換する

青空文庫テキスト → ruby 付き EPUB に変換するスクリプトは**既に動作している**
(`aozora2epub.py`、2026-08-10 作成)。

| 項目 | 内容 |
|---|---|
| 入力 | 青空文庫形式 (Shift-JIS / UTF-8 自動判別) |
| 出力 | EPUB 3.0 (`<ruby><rt>` 使用) |
| 対応 | `《》` / `｜` / 見出し注記 / 外字 (U+xxxx) / 凡例・底本の除去 |
| 実績 | 『最終戦争論』でルビ44・見出し15・段落244 を変換。記法の残存ゼロ |

**EPUB 側のルビは develop で動作するはず** (`#2665`)。
実機確認 (A-3) で裏が取れる。

| | 端末側で対応 (F-8) | PC側で変換 (Plan B) |
|---|---|---|
| 手間 | ファイルを入れるだけ | 変換の一手間が要る |
| 実装コスト | **高い可能性** | **ゼロ (完成済み)** |
| 配布価値 | 高い | 低い (スクリプトの配布は可能) |

**Plan B は「妥協」ではなく、F-8 が完成するまでの実用解として配布できる。**
リポジトリに `tools/aozora2epub.py` として同梱する価値がある。

## 6. 優先順位の判断

| 順 | 機能 | 理由 |
|---|---|---|
| 1 | **F-3 文字コード自動判別** | F-8 の絶対的前提。単独でも価値が大きい |
| 2 | **F-7 TXT 折り返しの O(n²)** | ルビ幅の計算を足す前に直しておく |
| 3 | **F-8 段階1 (記法の除去)** | 難易度が低く、効果が即座に出る |
| 4 | F-2 Markdown チェックボックス | プロジェクトの原点。設計は確定済み |
| 5 | **F-8 段階2 (ルビ描画)** | §4-1 の調査結果を見てから判断 |
| 6 | F-8 段階3 (注記) | 無くても実用になる |
| 7 | F-5 縦書き | 単独で1プロジェクト規模 |

> **F-8 段階1 は F-2 より前に置いた。**文字列処理だけで完結し、
> 描画層に触れないため、リスクが低く効果が確実。
