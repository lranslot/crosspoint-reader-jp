## 0. なぜやるのか

**日本語の著作権切れ文学は、事実上すべて青空文庫にある。**

青空文庫のテキストは独自のプレーンテキスト記法を持ち、**ルビが `漢字《かんじ》`
という形で本文中に直接書かれている**。したがって EPUB に変換しなくても、
TXT リーダーが `《》` を解釈できれば、**青空文庫のファイルをそのまま
ルビ付きで読める**。

これに対応した日本語リーダーは、それだけで存在価値がある。
上流には通らない機能だが (SCOPE.md の対象外)、フォークなら制約はない。

### 上流との関係

| 項目 | 判断 |
|---|---|
| 上流に出すか | **出さない。**日本語固有の記法であり、`SCOPE.md` の対象外 |
| 上流の変更を待つか | 待たない |
| ただし | ルビ描画の基盤に手を入れる場合、上流の EPUB 実装と衝突しないよう配慮する |

## 1. 青空文庫記法の全体像

### 1-1. 実測 (石原莞爾『最終戦争論』/ 112,650 B / Shift-JIS)

| 記法 | 出現数 | 例 |
|---|---|---|
| ルビ `《》` | 47 | `真面目《しんめんぼく》` |
| ルビ範囲指定 `｜` | 5 | `包囲｜殲滅《せんめつ》` |
| 注記 `［＃...］` | 77 | `［＃１字下げ］` |
| 外字 `※［＃...］` | **3** | `※［＃「衄のへん＋絆のつくり」、U+8845、62-12］` |

注記の内訳 **(2026-11-03 再集計。初版の見出し 15 / 外字 2 は誤り。§5.5)**:

| 種類 | 数 | 対応の要否 |
|---|---|---|
| `［＃N字下げ］` (行単位) | **31** | **29 は見出し行にある。本文段落には 1 つも無い** (§5.5-1) |
| `［＃「...」は大/中/小見出し］` | **29** | **うち 15 は「同行中見出し」**で、本文と同じ行にある。前後に空行を入れられない |
| `［＃ここから/ここで...］` | **2 組** | 範囲指定。どちらも 16 字・21 字で、日付と出典の行 |
| 外字 | **3** | U+xxxx が読めれば実文字に |
| 傍点 | **3** | **黙って消えている** (§3 段階3) |
| その他 (図の位置・底本注記) | 11 | **除去のみでよい** |

### 1-2. 記法の正確な仕様

#### ルビの親文字の決定規則

`｜` がある場合はその位置から `《` までが親文字。
無い場合は、**`《` の直前から遡って、同種の文字が続く範囲**が親文字になる。

同種の判定は以下の順:

1. 漢字 (`\u4e00-\u9fff` + `々〆ヶ`)
2. カタカナ
3. 英数字
4. ひらがな

> **`｜` が必要になるのは、親文字を自動判定できない場合。**
> 例: `包囲｜殲滅《せんめつ》` — `｜` が無いと「包囲殲滅」全体が
> 親文字になってしまう。

#### ファイル構造

```
1行目: 作品名
2行目: 著者名
（空行）
-------------------------------------------------------
【テキスト中に現れる記号について】
（凡例）
-------------------------------------------------------

（本文）

底本：「...」
（奥付）
```

**凡例ヘッダと底本フッタは本文ではない。**表示するなら除去すべき。

## 2. 【最重要】未確認の前提

**本機能の実現可能性は、以下の1点にかかっている。**

### 2-1. TXT リーダーはルビを描画できるのか

| 事実 | 出典 |
|---|---|
| TXT / EPUB / XTC は**完全に別クラス** | spec §6.2 |
| TXT は**視覚行1本につき `drawText` 1回**の行単位描画 | spec §6.2 (実測 約75回) |
| EPUB は `Page::render()` が単語・ラン単位で描く (約2,900回) | 同上 |
| ruby は `#2665` で EPUB に実装された。`TextBlock` がルビを保持 | spec 附録E |

**つまり、ルビの実装は `TextBlock` / `Page::render()` 側にある可能性が高く、
TXT リーダーからは使えないおそれがある。**

その場合、TXT にルビを出すには**描画層に新規実装が要る**。
これは「既存機能の再利用」ではなく「新機能の開発」であり、
工数の桁が変わる。

**調査 (§4) で最初に潰すべき前提。**

### 2-2. ルビが折り返しと行高に与える影響

ルビを出すと、以下が連鎖する。

| 影響 | 内容 |
|---|---|
| **行高** | ルビの分だけ行が高くなる。1ページの行数が減る |
| **折り返し幅** | **ルビが親文字より幅広の場合、その分を考慮しないと重なる** |
| **ページ分割** | 行高が可変になると `buildPageIndex()` の計算が変わる |
| **F-7 との干渉** | 折り返しが O(n²) の状態でルビ幅の計算を足すと、さらに遅くなる |

**F-7 (折り返しの O(n²) 修正) を先に済ませておく方が安全。**

### 2-3. Shift-JIS が読めないと何も始まらない

**青空文庫のテキストは Shift-JIS。**
F-3 (文字コード自動判別) が無ければ文字化けして読めない。**F-3 は実装済み (`3639c847`)。この前提は満たされている。**

**F-3 は F-8 の絶対的な前提条件。**

## 3. 実装の段階分け

依存関係を踏まえた順序。

### 前提: F-3 (文字コード自動判別)

**これが無いと青空文庫のファイルが読めない。**先に実装する。

### 段階1: 記法の除去 (最小)

**ルビを出さない。記法を消して読めるようにするだけ。**

| 対象 | 処理 |
|---|---|
| `《よみ》` | **除去** (親文字は残す) |
| `｜` | 除去 |
| `［＃...］` | 除去 |
| `※［＃...U+xxxx...］` | U+xxxx を実文字に。読めなければ `〓` |
| 凡例ヘッダ / 底本フッタ | 除去 |

**これだけでも実用価値がある。**いまは `《しんめんぼく》` が本文中に
そのまま表示されて読みにくい。

**難易度: 低。**文字列処理のみで、描画層に触れない。

### 段階2: ルビの描画

**§2-1 の調査結果次第で難易度が激変する。**

| 前提 | 難易度 | 内容 |
|---|---|---|
| TXT から既存のルビ基盤が使える | 中 | パース結果を渡すだけ |
| 使えない | **高** | 描画層に新規実装。行高・折り返しの改修を伴う |

必要な要素:

1. 行の解析時に、ルビの位置 (親文字の開始/終了、読み) を保持する
2. 折り返し計算にルビ幅を加味する
3. 行高をルビの有無で可変にする
4. 親文字の上にルビを描画する (小さいフォントサイズ)
5. ページ分割が行高の変化に追従する

**ルビ用のフォントサイズ**: 本文の約半分。8pt 前後になる見込み。
本文フォント (SD) に 8pt が必要になる可能性がある。**要検証。**

### 段階3: 注記への対応 (任意)

| 記法 | 対応案 |
|---|---|
| `［＃「...」は大/中/小見出し］` | 見出しとして扱う (太字・サイズ変更・目次生成) |
| `［＃N字下げ］` | 行頭にインデント |
| `［＃ここから/ここで...］` | 範囲指定の字下げ・字詰め |
| 傍点 (圏点) | **ルビ (段階2) の直後に実施する。ルビの仕組みを流用する。**場所の確保の問題がルビと同一 (横書きは `lineHeight`、縦書きは `columnWidth` が変わり、ページモデルが壊れる)。ルビが領域を確保する形で実装されれば、傍点はその領域に文字ではなく点を置くだけになる。**ルビ実装後に約 60〜80 行。**記法は `［＃「○○」に傍点］` / `［＃傍点］`…`［＃傍点終わり］`、種類はゴマ点 (既定) / 白ゴマ / 丸 / 白丸 / 黒三角 / 白三角 / 二重丸 / 蛇の目 / ばつ。**現状は段階1 の `［＃…］` 一般規則で黙って除去されており、作者の強調が失われている。**★ 前提: ルビが領域を確保する形で実装されること。EPUB 側の組版に渡す形なら流用できない |

**段階3 は無くても実用になる。**優先度は低い。

### 5.5-3 ★ 測り方を 1 度間違えた

最初の集計で「`戦争史大観` の範囲字下げは最大 **12 字**」と報告したが、

全角数字を拾う自前の関数が `１` と `２` を続けて読み、
**`12` という存在しない値を作っていた。**

正しい内訳 (『戦争史大観』29 ブロック):

| 記法 | 数 |
|---|---|
| `ここから１字下げ、折り返して２字下げ` | **17** |
| `ここから改行天付き、折り返して１字下げ` | **10** |
| `ここから１字下げ` / `ここから２字下げ` | 4 / 3 |
| `ここから２０字下げ` / `ここから１９字下げ` | 1 / 1 |
| `ここから罫囲み` / `ここから２段組` | 1 / 2 |

**27 / 29 が 0〜2 字。**大きいのは 2 件だけで、
どちらも『最終戦争論』の 16 字・21 字と同じ
**日付と出典の行**である（右寄せの代用）。

> **§8.7-19 の形がまた出た。**自分の集計を根拠に
> 「最大 12 字」と書き、その数字で崩れ方の議論を始めていた。
> **記法の実物を見るまで誤りに気づかなかった。**

### 5.5-4 ★ ぶら下げは変換時には書けない

段階1.5 は**変換時に剥がして、下流には記法の無いファイルを渡す**形である。
この形では**ぶら下げ（折り返した 2 行目以降も下げる）は実現できない。**

| | |
|---|---|
| 行頭に全角スペースを N 個入れる | **論理行の先頭にしか効かない** |
| 折り返した 2 行目を下げるには | 組む側が「この行は N 字下げ」という**情報を保持**する必要がある |
| それは誰の仕事か | `loadPageAtOffset()` ── **ルビが触る場所そのもの** |

**ハード折り返しで代用することもできない。**変換は 1 冊につき 1 度しか
走らないが、折り返し位置はフォントサイズ・余白・画面の向きで変わる。
変換時に改行を打ち込めば、**その時の画面の形が焼き付く。**

**→ ぶら下げは段階1.5 に含めない。**含めた瞬間に
「段階1.5 はページモデルに触らない」という
**ルビより先に置く理由そのものが消える。**

### 5.5-5 崩れ方 ── 範囲字下げを素朴に置換したとき

試し刷り (いずれも `mockups/`):

| 画像 | 内容 |
|---|---|
| `f8-ranged-small-naive.png` | **1 字下げ (17 件ある普通の形)。**横書き。ぶら下げ無しでも**問題無い** |
| `f8-ranged-h-now.png` / `f8-ranged-h-naive.png` | **19 字下げ。**横書き |
| `f8-ranged-v-now.png` / `f8-ranged-v-naive.png` | **19 字下げ。**縦書き |

| | |
|---|---|
| 横書きの 1 行 | **全角 18 字** (12 pt / 480 px / 余白 8+8) |
| 縦書きの 1 列 | **全角 29 字** |

**1〜2 字下げは何の問題も起きない。**番号付きの項目が 1 字下がり、
折り返しは行頭に戻る ── 普通に組まれた文章と区別がつかない。

**19 字下げは壊れる。**

| | 症状 |
|---|---|
| 横書き | **19 字 > 1 行の 18 字。**字下げだけで 1 行を使い切り、本文が次の行の頭から始まる。字下げが**消えたのと同じ**になり、空行が 1 本増えただけになる |
| 縦書き | 19 + 本文 17 = **36 字 > 1 列の 29 字。**行が 2 列に割れ、**前半が列の下端・後半が次の列の上端**に離れる。日付の 1 行が**ページの両端に分かれて読めない** |

**現状 (範囲字下げを捨てる) のほうが明らかに読める。**

### 5.5-6 ★ 青空文庫はぶら下げを記法で持っている

```
［＃ここから１字下げ、折り返して２字下げ］
```

**「折り返して N 字下げ」がぶら下げの指定そのものである。**
『戦争史大観』の 29 ブロック中 **27 がこの形**を使っている
（`折り返して２字下げ` 17 件 / `改行天付き、折り返して１字下げ` 10 件）。

**将来ぶら下げを実装するときの入力はここから取る。**
親文字の字数から推測する必要も、既定値を決める必要も無い。
**作者（入力者）が各ブロックについて明示している。**

段階1.5 の実装は `折り返して M 字下げ` を**読み飛ばすが、構文としては
認識している**（`classifyNote()` が `ここからN字下げ` の後に何が続いても
`、` 以降を無視して N を返す）。**M を使う側が現れたときに、
記法の解析を書き直す必要は無い。**

> ぶら下げを実装する場所は `loadPageAtOffset()` であり、
> それはルビが触る場所と同じである (§5.5-4、`f8-ruby.md`)。
> **ルビの設計がぶら下げの設計を兼ねる。**

### 5.5-7 実装 — 段階1.5 (2026-11-03)。**段階2g (2026-11-10) で置き換わった**

段階1.5 の処理（**現在はこうではない。**§5.5-8 が現行）:

| 対象 | 処理（段階1.5） |
|---|---|
| `［＃N字下げ］` | 行頭にあるときだけ、**全角スペース N 個**に置換 |
| `［＃ここからN字下げ］` | **N ≤ 2 のときだけ**、範囲内の各行の先頭に全角スペース N 個 |
| 同じく **N > 2** | **捨てる**（`indentTooWide` に計上） |
| `［＃ここで字下げ終わり］` | 範囲を閉じる |
| ブロック見出し | **前後に空行。**既に空行があるときは足さない |
| **同行見出し・窓見出し** | **触らない。**本文と同じ行にあり、空行を置く場所が無い |
| `折り返して M 字下げ` | 読み飛ばす（§5.5-6） |

`MAX_RANGE_INDENT = 2` の根拠は
[AozoraStrip.h](../lib/Aozora/AozoraStrip.h) のコメントに置いた。
**18pt 横書きで 1 行 12 字、2 字なら 17%。**

### 5.5-9 ★ 段階2h — 傍点を content.u8 に残す (2026-11-11)

| 対象 | 処理（現行） |
|---|---|
| `［＃「X」に傍点］` / `［＃「X」に白丸傍点］` ほか | **落とさず、そのまま content.u8 に残す。**読み手が外して点を描く |
| `［＃傍点］`…`［＃傍点終わり］` | **未対応。**従来どおり捨て、`Stats::boutenRange` に数える |
| `［＃「X」に傍線］` など傍点以外 | **従来どおり捨てる。**`傍点` で終わる注記だけが残る |

残す理由はルビ (§5.5-2) と同じ ── **記法は文字を名指しするが、
その文字がどこに来るかを知っているのは組版する側だけ**である。

種類は 4 ファイルの実測で `白丸` しか出ない（本編 5 件すべて）。
**既定のゴマ点は本編に 1 件も無い。**
詳細と検証は [f8-ruby.md §6.1 / §6.2](f8-ruby.md)。

### 5.5-8 ★ 段階2g — 字下げを行の属性にし、ぶら下げを実装した (2026-11-10)

| 対象 | 処理（現行） |
|---|---|
| `［＃N字下げ］` | 行頭にあるときだけ、その行の**先頭に正規化した記法を書く** |
| `［＃ここからN字下げ］` | **上限なし。**範囲内の**各行の先頭**に `［＃N字下げ］` を書く |
| `［＃ここからN字下げ、折り返してM字下げ］` | 同じく各行の先頭に `［＃N字下げ、折り返してM字下げ］` |
| `［＃ここで字下げ終わり］` | 範囲を閉じる |
| 読み手側 | 記法を**読んで飛ばす**（消さない）。升目単位で、生きた表示領域に合わせて切り詰める |

**変換時に範囲を解いて 1 行ずつに畳む。**理由は 2 つある。

1. **読み手は任意のファイル位置から組み始める**（F-9 の遅延ページ索引）。
   範囲の開始行を見ていない状態で 500 行目から始まることがあるので、
   **行が自分で自分を名乗らなければならない。**
2. **升目をピクセルに直せるのは表示領域を知っている側だけ。**
   変換時には画面の向きも文字サイズも分からない。

#### `MAX_RANGE_INDENT = 2` は撤廃した

段階1.5 の上限は**全角スペースに展開していたことの帰結**だった。
ファイルの数字は青空文庫の行長に対して選ばれていて、こちらの行長ではない
── `［＃ここから１９字下げ］` は右寄せを空白で代用した書き方なので、
18pt 横書きの 1 行 12 字にそのまま 19 個入れると行が溢れる。

属性にした今、**升目に合わせて切り詰めるのは読み手**である
（`TxtReaderActivity::clampIndent`、本文が `MIN_TEXT_CELLS = 4` 升は残る）。
数字そのものの健全性だけを `MAX_INDENT = 99`（全角 2 桁）で見る。
結果、**捨てていた行が出るようになった**:

| | 段階1.5 | 段階2g |
|---|---|---|
| 『戦争史大観』の範囲字下げ | 24 件（2 件は捨てた） | **26 件** |
| 同・ぶら下げ (`折り返して`) | **0 件**（全部読み飛ばし） | **17 件** |
| 『最終戦争論』の範囲字下げ | 0 件（2 件とも捨てた） | **2 件** |

切り詰めの効き方（14pt、`１９字下げ`）:

| 方向・サイズ | 1 行の升目 | 字下げの上限 | `１９字下げ` の結果 |
|---|---|---|---|
| 縦書き 14pt | 26 | 22 | 19（切り詰めなし） |
| 横書き 14pt | 16 | 12 | **12 に切り詰め** |
| 横書き 18pt | 12 | 8 | **8 に切り詰め** |

#### ぶら下げの意味

`折り返して M 字下げ` が無いときの折り返しは、**先頭と同じ N 字下げ**にする。
0 に戻すのではない ── 引用の塊として `［＃ここからN字下げ］` と書いたとき、
折り返した行だけ左端（縦書きでは上端）に跳ね返るのは組版として誤りである。

#### `LineAttr` に入れたのは 1 つだけ

指示では `indent` と `hangingIndent` の 2 つを足すことになっていたが、
**`indent` 1 つにした。**`LineAttr` は**視覚行**（折り返し後の 1 行）の属性で、
視覚行は 1 つの位置にしか描けない。2 つ持たせると
**折り返しを測ったときの値と描くときの値が食い違える**ようになり、
それはページの切れ目が実際の描画からずれる経路そのものである。
ぶら下げ量は**原稿行**の属性で、それを適用する組み立てループの外には出ない。
`indent` は「この視覚行に実際に適用した升目数」で、
切り詰めも済んだ値が入っている。

組版結果が旧実装と**バイト単位で一致**する。やり方は、
v6 の出力から読み手と同じ規則で先頭の記法を飛ばし、
**字下げを一切しない HEAD 実装**（`MAX_RANGE_INDENT = 0` 相当に潰したもの）の
出力と全文比較する。一致したので、**記法の置き場所を変えたこと自体は

#### 版の繰り上がり

| | 変更前 | 変更後 | 理由 |
|---|---|---|---|
| `ENCODING_VERSION` | 5 | **6** | `content.u8` の中身が変わる。全オフセットが動く |
| `CACHE_VERSION` | 9 | **10** | 字下げが升目を食うのでページの切れ目が動く |

> **指示の数字との差。**指示書は `ENCODING_VERSION 4 → 5` と
> `CACHE_VERSION 9 → 10` だったが、`ENCODING_VERSION` は
> ルビを残した段階2a で既に 5 になっていた。よって **5 → 6** である。

#### 構造の変更 — 出力を 1 行ずつ保持するようにした

**ブロック見出しは行の末尾で自分を名乗る**
（`［＃「第一章…」は中見出し］` が本文の後に来る）。
したがって**その行の前に空行が要るかどうかは、行を読み終わるまで分からない。**
出力を `out` に直接足していては、もう書いた後なので挿入できない。

`lineOut_` に 1 行ぶんを溜め、改行で `flushLine()` が吐く形にした。
上限は **4096 バイト**で、超えた行はその場で解放し、その行の空行判定だけを飛ばす。
**上限は行に対してかけてあり、チャンクに対してではない** —
呼び出し側が何バイトずつ読んでも、同じファイルは同じバイト列に変換される。

#### 変換の最後が落ちる経路を 1 つ塞いだ

`Txt::convertToUtf8()` は読み込みが 0 バイトになったとき
`atEnd=true` を渡さずに `break` していた。
ファイルの長さが `CONVERT_CHUNK` (8192) の**ちょうど倍数**のとき、
どの周回も `atEnd` にならないまま終わる。
行を保持するようにした以上、**最後の 1 行が落ちる。**
`avail == 0` の経路でも `process("", 0, ..., atEnd=true)` を呼ぶようにした。

> これは行保持を入れる前から `carry_`（入力側の保持）にも当てはまる穴だった。
> **保持するものを増やしたことで、初めて実害のある形になった。**

#### `ENCODING_VERSION` 3 → 4

**繰り上げが要る。**`content.u8` のバイト列が変わるためである。

| | |
|---|---|
| ページ索引 | `content.u8` への**バイト位置**の配列。中身がずれれば全部無効 |
| 読書位置 | 同じく**バイト位置**で保存されている |

`Txt.cpp` は変換のたびにページ索引を捨てるので、
**版を上げれば索引と進捗は自動で作り直される。**
設定ではなく版にしたのはこのためで、
**同じ本が設定によって別のバイト列になる状態を作らない。**

#### 規則の検証（実データ 3 冊）

ホストのコンパイラが無いため **C++ そのものは PC で動かせない。**
`classifyNote()` と同じ判定を Python に写して、
3 冊の注記すべてに当てて分類を確かめた。

| | 最終戦争論 | 戦争史大観 | 新日本の進路 |
|---|---|---|---|
| 注記 | 77 | 206 | 6 |
| ブロック見出し | **14** | 44 | 0 |
| 行単位の字下げ | 29 | 47 | 0 |
| 範囲開始 | 2 | 37 | 1 |
| **うち適用 (N ≤ 2)** | **0** | **24** | **1** |
| **うち破棄 (N > 2)** | **2** (16, 21) | **2** (19, 20) | 0 |
| その他（捨てるだけ） | 30 | 49 | 4 |

**同行見出し 15 件は見出しに数えられていない**（14 = 29 − 15）。狙いどおり。

**これは規則の検証であって、C++ の検証ではない。**
転記の誤りは実機でしか出ない。

## 6. 優先順位の判断

| 順 | 機能 | 理由 |
|---|---|---|
| 1 | **F-3 文字コード自動判別** | F-8 の絶対的前提。単独でも価値が大きい |
| 2 | **F-7 TXT 折り返しの O(n²)** | ルビ幅の計算を足す前に直しておく |
| 3 | **F-8 段階1 (記法の除去)** | 難易度が低く、効果が即座に出る |
| 4 | F-2 Markdown チェックボックス | プロジェクトの原点。設計は確定済み |
| 5 | **F-8 段階2 (ルビ描画)** | §4-1 の調査結果を見てから判断 |
| 6 | F-8 段階3 (注記) | 無くても実用になる |
| 7 | F-5 縦書き | 単独で1プロジェクト規模 |

> **F-8 段階1 は F-2 より前に置いた。**文字列処理だけで完結し、
> 描画層に触れないため、リスクが低く効果が確実。
