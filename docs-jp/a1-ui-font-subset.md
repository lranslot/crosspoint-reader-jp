## 0.5 ★ 焼き込みは SD を不要にしない (2026-10-27 追記)

**この文書の初版は「焼き込めば SD 依存が消える」と読める書き方になっていた。
誤りである。**

| | 何を描くか | 出どころ |
|---|---|---|
| **焼き込む 349 字** | **UI の固定文言だけ** (`tr()` が返すもの) | `japanese.yaml` |
| **SD の利用者フォント** | **ファイル名・書名・著者名・章題・SSID・エラー文字列** | ファイルシステム / EPUB / 利用者入力 / 通信 |

**予測できない文字は焼き込めない。**よって:

> ### 利用者への前提: **8/10/12/14/16/18 の 6 サイズすべてを生成すること**
>
> 1 サイズでも欠けると、そのサイズを使う画面で**任意の文字が豆腐になる。**
> 配布手順書 (`phase-e-release-checklist.md`) に必ず書く。

**焼き込みの目的は「SD が無くても設定画面を操作できる」という保険であり、
SD を不要にすることではない。**

### なぜ劣化が綺麗に収まるか — `resolveTextFontId()` は文字列単位

`GfxRenderer::resolveTextFontId()` は **private で、文字列全体を走査して
id を 1 つだけ返す** (仕様書 §8.1-7)。

**1 文字でも欠ければ、その文字列はまるごとフォールバック側で描かれる。**

| 結果 | 内容 |
|---|---|
| **書体が文字ごとに混ざらない** | 「この漢字だけ別の書体」という崩れ方をしない |
| **豆腐は文字列単位で出る** | 1 行まるごと読めるか、1 行まるごと読めないか |

**これは設計上の利点である。**部分的に欠けた表示より、単位が揃っている方が
「このフォントが足りていない」と利用者に伝わる。

### ★ `SMALL` (8 pt) で任意の文字を描いている箇所 — **特記**

**8 pt は利用者が生成しない可能性が最も高いサイズである。**
にもかかわらず、任意の文字を描いている箇所が多い:

| # | 箇所 | 深刻度 |
|---|---|---|
| 1 | **ステータスバーの書名** | **高。**読書中つねに表示される |
| 2 | **一覧の副題と右端の値** (`GUI.drawList`) | **高。**ファイル一覧・しおり・目次すべて |
| 3 | **現在のフォルダのパス** | 中 |
| 4 | **最近読んだ本の書名 (Lyra 3 面テーマ)** | 中。テーマ依存 |
| 5 | Calibre の状態文字列 | 低 |
| 6 | ボタンヒント (降格したとき。`9063c0f9`) | 中 |

**8 pt 面が無いと、これらが一斉に豆腐になる。**
`setupUiFallbacks()` は pt を厳密一致で登録するため、近いサイズには落ちない。

→ **「6 サイズすべて生成」が前提として必須である理由がここにある。**

## 0.7 ★ ウェブのフォントビルダー (2026-10-27 追記)

**crosspointreader.com の `/fonts` に、ウェブのフォントビルダーがある。**

| | |
|---|---|
| **中身** | **我々のリポジトリにあるのと同じ `fontconvert_sdcard.py`** |
| 実行 | GitHub Actions の `build-fonts.yml` |
| 利用者が指定できるもの | TTF/OTF を最大 4 スタイル + フォールバック用の別ファミリ 2 つ / ファミリ名 / ポイントサイズ / Unicode 範囲 (プリセットまたは任意指定) |

**Phase B の作業がウェブ側と重複しないかの判断に効く。**
焼き込み用の面を作る処理は、**ビルダーと同じスクリプトで足りる可能性が高い。**

> **→ 文字集合もポイントサイズもメトリクスも、すべて利用者依存である。**
> 配布先の構成を前提にできない (仕様書 §3.6)。

## 3. フォント生成の仕組み (調査項目 5)

`lib/EpdFont/scripts/fontconvert.py` の実測。

| 項目 | 実測値 |
|---|---|
| サイズ指定 | `face.set_char_size(size << 6, size << 6, 150, 150)` (:268) → **pt 指定・150 DPI** |
| ビット深度 | 既定 **1-bit**。`--2bit` で2ビットグレースケール |
| ビットマップの詰め方 | **連続ビットストリーム**。`dataLength = ceil(width × height / 8)`。**行のバイト境界揃えは無い** (出荷済みヘッダ5本で検証) |
| 圧縮 | `--compress` で DEFLATE。グループ単位 |
| 収録範囲の指定 | `--additional-intervals min,max` の**繰り返し**。単独文字は `X,X` |
| 1グリフの構造体 | `EpdGlyph` = 14 B (`width`1 + `height`1 + `advanceX`2 + `left`2 + `top`2 + `dataLength`2 + `dataOffset`4) |
| 区間の構造体 | `EpdUnicodeInterval` = 12 B |
| フォントスタック | 複数 TTF を優先順に指定可。**先勝ち** |

### 現在の UI 5面の生成設定

**いずれも 1-bit・無圧縮。** 本文フォント (notosans_12 以降) は `--2bit --compress --pnum` を使っている。
**UI 面で `--compress` はまだ使われていない。**

| 面 | ビットマップ | グリフ数 | ビットマップ/字 |
|---|---|---|---|
| `ubuntu_10_regular` | 23,522 B | 1,032 | 22.8 B |
| `ubuntu_10_bold` | 26,693 B | 1,032 | 25.9 B |
| `ubuntu_12_regular` | 32,540 B | 1,032 | 31.5 B |
| `ubuntu_12_bold` | 36,561 B | 1,032 | 35.4 B |

### 実測: 日本語グリフのコスト

`fontconvert.py` と同一の設定 (FreeType / `set_char_size(size<<6, size<<6, 150, 150)` / 1-bit /
`ceil(w×h/8)`) で **Noto Sans CJK を実際にラスタライズして計測した。**

**対象は §2 の 349字。**

| 面 | em | ビットマップ | グリフ表 | 計 (無圧縮) | DEFLATE 後 |
|---|---|---|---|---|---|
| `ubuntu_10_regular` | 20.8 px | 15,644 B | 4,886 B | 20,530 B | 15,690 B |
| `ubuntu_10_bold` | 20.8 px | 16,431 B | 4,886 B | 21,317 B | 16,107 B |
| `ubuntu_12_regular` | 25.0 px | 22,967 B | 4,886 B | 27,853 B | 18,831 B |
| `ubuntu_12_bold` | 25.0 px | 23,939 B | 4,886 B | 28,825 B | 19,523 B |
| `notosans_8_regular` | 16.7 px | 10,960 B | 4,886 B | 15,846 B | 12,766 B |
| **合計** | | | | **114,371 B (112 KB)** | **82,917 B (81 KB)** |

かな・記号を含む 349字の平均より高いのは、漢字が最も墨の多い字種であるため。

## 5.5 ★ 2026-10-27 の実測で確定した数字

初版の試算を実際のビルドで裏取りした。

### 容量の収支

| 項目 | バイト | 備考 |
|---|---|---|
| 現在の Flash 使用 | 5,628,491 B (85.9%) | A8 込み |
| **現在の空き** | **925,109 B (903 KB)** | 初版の「910 KB」とほぼ一致 |
| 焼き込み 349 字 x 5 面 | **−114,371 B (−112 KB)** | 1-bit |
| **焼き込み後の空き** | **810,738 B (792 KB)** | |
| (任意) `en` / `ja` 以外を削除 | **+306,358 B (+299 KB)** | **実際にビルドして計測** |
| **両方やった場合の空き** | **1,117,096 B (1,091 KB)** | |

> **初版の「30言語削除で 323 KB」は試算。実測は 299 KB。**約 24 KB 少ない。
> 文字列表だけで 300,884 B 減り、残りはキーボード配列などのコード。

**→ 判定: 入る。言語削除は前提条件ではない。**
焼き込みだけでも 792 KB 残る。

### 面の構成 (確定)

| 問い | 答え |
|---|---|
| 112 KB は 1 サイズぶんか | **違う。3 サイズ 5 面の合計** |
| **bold は要るか** | **要る。**`UI_12` + BOLD が **43 箇所**、`UI_10` + BOLD が **17 箇所** |
| **italic は要るか** | **不要。UI では 0 箇所** (参照は SD のスタイル代替表と EPUB パーサのみ) |
| **8 pt の bold は要るか** | **不要。0 箇所** |
| **`is2Bit` の影響** | **無い。UI フォントは全面 `is2Bit = false` (1-bit)** |

**`is2Bit` について**: 本文フォントと SD フォントは 2-bit だが、
**UI フォント 5 面はすべて 1-bit。**A-1 の試算も 1-bit なので一致する。
仮に 2-bit にするとビットマップが倍 (89,941 → 179,882 B) で合計 200 KB。
**それでも入るが、UI を 2-bit にする理由が無い。**

### 言語依存コードの量 (軸 A の作業量)

**翻訳表以外に `Language::` を参照しているのは 3 ファイルだけ。**

| ファイル | 件数 | 内容 |
|---|---|---|
| `lib/I18n/I18n.cpp` | 5 | 言語の解決 |
| `lib/I18n/I18n.h` | 1 | |
| `src/activities/util/KeyboardEntryActivity.cpp` | 3 | **FR/DE/ES のキーボード配列** |

**加えて、生成ファイルに 1 箇所ある**:
`scripts/gen_i18n.py` の `V1_LANGUAGES` — `language.bin` の V1 形式を読むための
**凍結された移行表** (22 言語)。言語を消すと**コンパイルが通らなくなる。**
これは意図的な設計で、「移行表を更新しろ」という合図である。

> **軸 A をやるなら、この移行表の扱いを決めるのが本体の作業になる。**
> 翻訳ファイルを消すこと自体は `rm` で済む。

### ★ ファイル名に出る文字は既に入っている

**追加は 0 字。**数字・`.`・`-`・`_`・拡張子 (`txt` / `epub` / `md`) は
**すべて ASCII 95 字に含まれており、Ubuntu / NotoSans に元から入っている** (§2)。

**→ SD が無くても、ラテン文字のファイル名は完全に読める。**
日本語の書名は読めないが、**拡張子と番号で見当がつく。**
これは焼き込み 349 字の範囲を広げなくても既に成立している。

---

## 6. 判断: **UI サブセットのみを採る**

常用漢字・第1水準まで焼けば、書名や著者名も SD フォント無しで表示できるようになる。
容量も足りている。**それでも採らない理由は3つある。**

**1. 常用漢字では書名・人名を救えない。**
実例として『最終戦争論』の著者「石原莞爾」の **莞・爾はいずれも常用漢字ではない。**
中途半端に増やしても「たまに読める」が「たまに豆腐」は残る。**問題の性質が変わらない。**

**2. §4.1 の設計が既にこの問題を解いている。**
書名・著者・ファイル名は本文フォント経由にする。本文フォントはユーザーが選ぶ以上、
必ず SD に存在する。**フル字形が使えるので、第1水準ですら足りない字も表示できる。**

**3. 焼き込みの目的は「日本語 UI がフォント無しで成立すること」であり、それは 349字で達成される。**
UI が読めれば、フォントを SD に置く操作まで自力でたどり着ける。
**「読めない UI から抜け出せない」事故が原理的に起きない**という §4.1 の狙いは、112 KB で満たされる。

余った 1,121 KB は、将来の機能 (F-8 ルビ描画、F-5 縦書き) と OTA の安全余裕に残す。

## 7. 文字集合の再生成スクリプト

`japanese.yaml` を編集するたびに文字集合は変わる。**Phase B ではこれをビルド時に走らせる**のが確実。

```python
#!/usr/bin/env python3
"""UI フォントに焼き込むべき非 ASCII 文字を japanese.yaml / english.yaml から抽出する。"""
import re, sys, pathlib

TRANSLATIONS = pathlib.Path("lib/I18n/translations")
# 翻訳ファイルに現れないが UI フォントで描かれる文字
EXTRA = "…"          # GfxRenderer::truncatedText() の省略記号 (U+2026)

def values(path):
    out = []
    for ln in path.read_text(encoding="utf-8").splitlines():
        m = re.match(r'^([A-Za-z_][A-Za-z0-9_]*):\s*"(.*)"\s*$', ln.rstrip())
        if m:
            out.append(m.group(2).replace('\\n', '\n').replace('\\"', '"'))
    return "".join(out)

blob = values(TRANSLATIONS / "japanese.yaml") + values(TRANSLATIONS / "english.yaml") + EXTRA
chars = sorted({c for c in blob if ord(c) > 0x7F})

# fontconvert.py 用の引数 (1文字ずつの区間) を出力
for c in chars:
    print(f"--additional-intervals 0x{ord(c):04X},0x{ord(c):04X}")
print(f"# {len(chars)} characters", file=sys.stderr)
```

## 8. ⚠️ Phase B に持ち越す課題

数値は解決したが、**手順の面で未解決の点が4つある。**

### 8.1 コマンドライン長の上限

`--additional-intervals` は区間の繰り返しでしか指定できない。349字が CJK 領域に散らばっているため、
**約349個の区間指定**が必要になる。1個あたり約35文字で **12 KB 超**。

**Windows の `cmd.exe` はコマンドライン 8,191 文字が上限。**そのままでは通らない。

対策の候補:

| 案 | 内容 |
|---|---|
| **A** | `fontconvert.py` に `--charset-file` を足す (フォーク独自の変更。**推奨**) |
| B | PowerShell から配列で渡す (cmd の制限は回避できるが、可読性が落ちる) |
| C | 連続する符号位置をまとめて区間に畳む (かな・約物には効くが、漢字230字はほぼ畳めない) |

**A が素直。** `gen_i18n.py` と同じく `platformio.ini` の `extra_scripts` に載せれば、
翻訳を書き換えるたびに自動で追随する。

### 8.2 日本語のソースフォントが無い

`lib/EpdFont/builtinFonts/source/` にあるのは NotoSans / NotoSerif / NotoSansArabic /
NotoSansHebrew / OpenDyslexic / Ubuntu の6種で、**CJK は1つも無い。**

追加が必要。**ライセンスは再配布可能なものに限ること。**

| 候補 | ライセンス | 備考 |
|---|---|---|
| Noto Sans JP | OFL 1.1 | 上流と同じ系統。字面の統一が取りやすい |
| BIZ UDPGothic | OFL 1.1 | UD 系。小サイズの可読性が高い |
| UDEVGothic | OFL 1.1 | 羅闇さんが SD で使っているもの。見た目の一貫性は最も高い |

> **Ubuntu (ラテン) + 日本語フォント (CJK) の混植**になる。`fontconvert.py` は
> フォントスタックを優先順で受け取れるので、機構としては既に用意されている。
> 字面が揃うかは**実機で見て判断すること。**

### 8.3 `--compress` を UI 面に使うかは要検討

DEFLATE で 112 KB → 81 KB になるが、**容量は足りているので圧縮する動機が弱い。**

一方で、圧縮はグループ単位の展開が要る。**UI は常時描画されるため、展開コストが
描画速度に直接効く。**F-6 (日本語 UI の描画性能) で一度苦労した領域である。

**まず無圧縮で焼くこと。**容量が逼迫していない以上、リスクを取る理由がない。

### 8.4 `notosans_8_regular` は bold を持たない

`SMALL_FONT_ID` は regular 1面のみ。`drawText(SMALL_FONT_ID, ..., EpdFontFamily::BOLD)` を
呼んでいる箇所があるかを確認し、**あるなら 8pt bold を新設するか、regular へのフォールバックで
問題ないかを決めること。**現状の豆腐問題 (ステータスバーの `最終◆◆◆`) はこの面で起きている。

---

## 8.5 ★ Phase B の要件: 12 pt が 2 つの書体で描かれる

Phase B 後、**同じ 12 pt が 2 つの異なる書体で描かれる。
これは設計であって不具合ではない。**

| 描くもの | 参照先 | 理由 |
|---|---|---|
| **文字設定のプレビュー行** | **利用者の SD フォント** | **読む書体を確認するための表示である** |
| タブ・ヒント・設定項目 | **焼き込んだ UI フォント** | SD が無くても操作できる必要がある |

> **⚠️ 要件: プレビュー行は SD 側を参照し続けること。**
> うっかり UI フォントに寄せると、**利用者が自分の生成したフォントを
> 確認できなくなる。**設定画面でフォントを選ぶ意味がなくなる。

該当は `src/activities/settings/TextSettingsPreview.cpp`。
