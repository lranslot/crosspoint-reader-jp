# 2. フォークの設計方針 (確定事項)

| 項目 | 決定 | 理由 |
|---|---|---|
| **ベース** | upstream/develop `596f0d3f` で固定 | `<ruby>` 等の日本語本文レンダリング改善4件が develop 限定 |
| **追随** | 常時追随しない。必要時に判断してリベース | 動いているものを壊さない |
| **UI フォント** | 日本語サブセットを Flash に焼き込み | フォント未設置でも日本語UIが成立。「読めないUIから抜け出せない」事故を防ぐ |
| **本文フォント** | ユーザーが選ぶ SD フォント | 好みの書体で読めるべき |
| **ファイル名・書名** | 本文フォントで描画 | 何の文字が入るか事前に決まらないため |
| **対応言語** | 英語 + 日本語のみ | 他30言語を削除して Flash を捻出。**英語は避難先として必ず残す** |
| **配布形式** | `.bin` のみ | ロック品・非ロック品の両方で使える唯一の経路 |
| **上流バグ** | 自前で修正する | #2949 / #2950 / #2650 |
| **リポジトリ** | 日本語主体 | 想定読者がほぼ日本語話者 |

# 3. 作業計画

## 3.1 Phase A: 基盤の移行 — **次の作業**

### A-1. UI サブセット文字の抽出 (調査)

**目的**: 焼き込むべき文字の確定と、容量の見積もり。

調査項目:

| # | 内容 |
|---|---|
| 1 | `japanese.yaml` の**値**に出現する文字を重複なく抽出 (キー名・メタ行は除外) |
| 2 | ひらがな / カタカナ / 漢字 / ASCII / 全角記号・約物 に分類し、それぞれの文字数 |
| 3 | 漢字は**一覧を全て報告** (人間が精査するため) |
| 4 | **翻訳ファイルに現れないが UI で描画される文字**の洗い出し (書式指定子に埋まる値、日付・時刻、数字、単位記号、エラーコード) |
| 5 | `fontconvert.py` を読み、bpp・1グリフあたりのメタデータ構造・配置先を確認 |
| 6 | 組み込みフォント (`ubuntu_10/12`, `notosans_8`) の実グリフ数とバイト数を測定し、**1グリフあたりの平均バイト数**を算出 |
| 7 | 31言語削除による削減量の概算 |
| 8 | 総合見積もり: (1+4の文字数) × (6の平均) × 3サイズ × 2ウェイト vs 残 Flash 963KB |

> **ASCII 95文字は全て含める。**3サイズ2種でも数十KB。削る意味がない。

**想定**: UI 文言は語彙が限られるため、漢字は 300〜500字程度に収まる見込み。
もし想定より多ければ、**訳文側で同義語を統一して漢字の種類を減らす**手もある
(「読み込み」と「読込」の混在を片方に寄せる等)。フォークならではの最適化。

# 6. 判断の記録 (v0.3 で確定したもの)

| 判断 | 結論 | 根拠 |
|---|---|---|
| ベースを 1.5.0 と develop のどちらにするか | **develop** | `<ruby>` を含む日本語本文レンダリング改善4件が develop 限定 |
| キャッシュ再生成を受け入れるか | **受け入れる** | 初回のみの待ち時間。データ損失なし。新規配布なら最初から develop 系 |
| 上流の翻訳拒否は覆せるか | **覆せない** | 同梱フォントの字形収録範囲という技術的境界。HE/AR が通ったのは UI フォントに字形があるため |
| UI フォントを焼き込むか | **焼き込む** | 上流の懸念 (壊れたUIの出荷) を原理的に解消する唯一の手段 |
| 他言語を削除するか | **削除する (英語は残す)** | Flash をフォントに回す。英語は避難先として必須 |
| F-2 を上流に確認するか | **確認しない** | SCOPE/ROADMAP の記述から答えは明白。Discussion で公開の「no」を記録に残す方が損 |
| `_order` を 31 と 32 のどちらにするか | **32** | 31 は open な #2908 が取得済み。どちらが先にマージされても衝突しない唯一の値 |
| PRテンプレートの master リンクは報告すべきか | **報告しない** | master と develop が同一コミットを指しており、バグではない |
