## 2.5 ボタンヒント — **本項が今回の中核**

### 経緯

1. `596f0d3f` の時点で「ダウンロード」「レイアウト」が枠外にはみ出し、
   隣の枠と重なっていた
2. `#2928` (`81028d58`) を取り込んだところ、**はみ出しは解消したが
   「ダウン…」と切り詰められる**表示になった
3. 原因を調査し、**枠拡張では解決できない**ことが数値で確定した

### #2928 の実装と限界

`BaseTheme::drawHintLabel()` が新設され、Base / Lyra の両方から呼ばれる。

```
constexpr int textPadding = 4;
const int maxTextWidth = boxWidth - (textPadding * 2);
if (textWidth <= maxTextWidth) { 1行で中央寄せ; return; }
const auto lines = renderer.wrappedText(fontId, label, maxTextWidth, 2);
```

| 項目 | 実測 |
|---|---|
| 折り返しの実装 | `wrappedText` を使用 (BaseTheme.cpp:174) |
| 折り返し位置 | **半角スペースのみ** (GfxRenderer.cpp:1632 `remaining.find(' ')`) |
| 折り返せない場合 | GfxRenderer.cpp:1660-1666 で `truncatedText()` を1行 push して return |
| 切り詰めの中身 | `utf8RemoveLastChar` で末尾から削り `…` を付す。UTF-8 境界は守る |
| **副作用** | **`textPadding` 導入で収容幅が 106 → 98 px に狭まった** |

**日本語ラベルは空白を含まないため、2行折り返しのパスに入らない。**
必ず「単語1個が幅超過」の分岐に落ち、1行の切り詰めになる。
**Issue #2949 と同じ根。**

### 枠の寸法 (実測)

| テーマ | 枠幅 | フォント | 実効テキスト幅 | 決まり方 |
|---|---|---|---|---|
| **BaseTheme** | 106 px | UI_10 (10pt) | **98 px** | `constexpr int buttonWidth = 106` (固定) |
| **LyraTheme** | 80 px | SMALL (8pt) | **72 px** | `constexpr int buttonWidth = 80` (固定) |
| Lyra3CoversTheme | 同上 | 同上 | 同上 | LyraTheme を継承。未オーバーライド |
| **RoundedRaffTheme** | 215 px に2ラベル | SMALL (8pt) | 実質 ~91 px | `(pageWidth - 40 - 10) / 2` (**動的**) |

X4 のボタン X 座標: Base `{25, 130, 245, 350}` / Lyra `{58, 146, 254, 342}` (固定値)。
**物理ボタンの位置に対応しているため動かせない。**

### 【結論】枠拡張では解決できない

| 検証 | 結果 |
|---|---|
| BaseTheme のボタン間ギャップ | `[-1, 9, -1]` — **ボタン1↔2 と 3↔4 は既に 1px 重なっている** |
| X 座標を動かさずに広げられる幅 | 均一にするなら **105 px = 現状より狭い**。つまり **1px も広げられない** |
| 6文字 (ダウンロード) に必要な幅 | テキスト 125 px = 枠 133 px |
| 4ボタン分 | **133 × 4 = 532 px > 画面幅 480 px** |
| 動的計算を導入した場合の最良値 | 枠 108 px / テキスト 100 px = **4.81 文字** (現状 4.70 から +0.1 文字) |

**左右余白をゼロにしても物理的に不可能。**

### テーマ別の収容力

UI_10 の CJK em = 20.8 px / SMALL = 16.7 px (150 DPI 基準、等幅前提の概算)。

| テーマ | 実効幅 | 収容文字数 |
|---|---|---|
| BaseTheme (UI_10) | 98 px | **4.70 → 実質4文字** |
| LyraTheme (SMALL) | 72 px | **4.32 → 実質4文字** |

### RoundedRaffTheme — 実機では溢れない

`drawHintLabel` を使わず生の `drawText` で左寄せ/右寄せ。**#2928 の対象外。**
理屈の上では対応漏れだが、**枠が広いため実機では「ダウンロード」6文字が
そのまま収まる**ことを確認した。

**実害がないため上流への報告は見送る。**

### ⚠️ TXT の折り返しに次に触るときの前提

`TxtReaderActivity::loadPageAtOffset()` と `GfxRenderer::findWrapOffset()` には、
**過去に踏んだ罠の対策が積み重なっている。**書き換える際は:

1. `[ ]` / `[x]` / `[X]` を**すべて `x` の幅として測る**という要件を壊さないこと
   (壊すと、トグルのたびにページ境界の行が消える)
2. `buildPageIndex()` と `render()` が**同じ折り返しをする**状態を保つこと
3. **折り返しの結果が変わったら `CACHE_VERSION` を上げること。**
   キャッシュの検証項目にビューポートはあるが折り返しアルゴリズムを表すものが無く、
   古い `pageOffsets` が黙って再利用される
4. `findWrapOffset()` は**リガチャペア (ﬀ / ﬁ / ﬂ) の中間では折らない。**
   旧実装は折れたが、O(n) 走査ではペアを不可分として扱う。差は行末の最大1文字
5. **RTL は旧経路にフォールバックしている。**`resolveVisualText()` の bidi 並べ替えにより
   前進スキャンのオフセットが logical 位置に対応しないため
6. **固定小数点のまま積むこと。**SD フォント経路は最後に1回しか `fp4::toPixel()` を
   呼ばない。ピクセル単位で足し込むと丸め誤差で結果が変わる

詳細は `docs-jp/f2-markdown-checkbox.md` §2.4 / §3.3 / §3.4 と仕様書 §6.7。

> **F-8 の詳細は `docs-jp/f8-aozora-notation.md` を参照。**

# 6. 判断の記録

| 判断 | 結論 | 根拠 |
|---|---|---|
| ベースを 1.5.0 と develop のどちらにするか | **develop** | `<ruby>` 等の日本語本文レンダリング改善4件が develop 限定。**実機で ruby 表示を確認済み** |
| ベースを `596f0d3f` から動かすか | **`81028d58` へ引き上げ** | 実機でボタンヒントの枠溢れを確認。#2928 が修正する。#2945 は親のため巻き込むが日本語には無関係 |
| ボタンヒントの枠を広げるか | **広げない** | 6文字には 133×4 = 532 px 必要で 480 px の画面に入らない。BaseTheme は X 座標を動かさずには 1px も広げられず、X 座標は物理ボタンに対応している |
| 訳語を短縮するか | **4件のみ短縮** | BaseTheme で確実に効く唯一の手段。`STR_CANCEL` は共用7箇所への波及を避けて据え置き |
| `RoundedRaffTheme` の対応漏れを報告するか | **見送り** | 枠が広く実機で溢れない。実害のないバグは報告しない |
| キャッシュ再生成を受け入れるか | **受け入れる** | 実測2〜3秒。手順書への注意書きも不要 |
| 上流の翻訳拒否は覆せるか | **覆せない** | 同梱フォントの字形収録範囲という技術的境界 |
| UI フォントを焼き込むか | **焼き込む** | 上流の懸念を原理的に解消する唯一の手段 |
| F-2 を上流に確認するか | **確認しない** | SCOPE/ROADMAP から答えは明白 |
| `_order` を 31 と 32 のどちらにするか | **32** | #2908 が 31 を取得済み。どちらが先にマージされても衝突しない唯一の値 |
| F-3 の変換をどこで行うか | **初回オープン時に変換してキャッシュ** | 1行ずつ変換すると開くたびに負担が乗り、長さが変わって `pageOffsets` と F-2 の `markOffset` が壊れる。この方式ならリーダー本体に手を入れずに済む |
| CP932 変換表を SD に置くか | **置かない。Flash に焼き込む** | `.bin` のみの配布 (§4.4) が崩れ、置き忘れで青空文庫が黙って読めなくなる。§4.1 で潰した事故と同型。規模もフォント1個の 1/300。**フラットな表は「Flash を使って CPU を買う」選択で、低速な端末では正しい** |
| F-7 のリガチャ境界の差異をどう扱うか | **新実装を採用** | 実機検証で19件の不一致はすべてリガチャペアの中間で、差は常に1文字。組版として不正ではなく、日本語 (SD フォント経路) は影響ゼロ |
| 読書位置をページ番号で持つか | **オフセットに変える (F-9)** | ページ番号は全ページを数え終わらないと意味を持たず、遅延構築を阻む。オフセットならフォント変更時の位置ずれも直る |
| F-9 でキャッシュ無効化時に1ページ目から始めるか | **始めない。オフセットで再開する** | `saveProgress()` は描画のたびに走るため、1ページ目から始めるとその瞬間にしおりが消える。**フォントサイズの変更でキャッシュは日常的に無効化される** |
