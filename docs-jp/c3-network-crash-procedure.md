# 焼き10 の確認手順 ── ネットワークのクラッシュ

> 焼き10（`9ef46d7e`）で確認する。**機能は足していない。**
> 載っているのは計器（`reset reason` と `/heap.txt` の 6 tag）と
> 書き込み確認の文言だけである。
>
> ★ **区別したいのは 2 つだけ。**
>
> | | 正体 | 決め手 |
> |---|---|---|
> | **(A)** | **確保失敗**（ヒープが足りない） | `Reset reason: PANIC` ＋ `/heap.txt` の `net-scan-start` で `max` が小さい |
> | **(B)** | **ブラウンアウト**（電源が足りない） | `Reset reason: BROWNOUT` ＋ ヒープは普通のまま |
>
> 決定的な実験は **USB 給電中と電池のみで同じ操作をすること。**
> (A) なら電源に関係なく落ち、(B) なら USB 中は落ちない（か落ちにくい）。

## 落ちたあとに見るもの

USB を挿して SD を PC に繋ぎ、**2 つのファイル**を見てください。

### 1. `crash_report.txt`（SD のルート）

★ **先頭の 2 行が今回の答えです:**

```
CrossPoint version: 1.5.0-jp-dev-9ef46d7e

Reset reason: ■■■■■■            ← ★ ここ

Panic reason: ...
```

| `Reset reason` | 意味 |
|---|---|
| **`PANIC`** | → **(A) 確保失敗**の線。`Panic reason` も埋まっているはず |
| **`BROWNOUT`** | → ★ **(B) 電源**で確定。ヒープは無関係 |
| `TASK_WDT` / `INT_WDT` | どこかが固まった。(A)(B) とは別の第 3 の筋 |
| `SW (esp_restart)` | 正常再起動。**クラッシュではない** |
| `POWERON` / `EXT` | 電源の入れ直し。前回の記録が残っていただけ |

`Panic reason` が空のときは、そのすぐ後ろに
`(empty: this reboot did not go through panic_abort(); read the reset reason above)`
と出ます。

### 2. `/heap.txt`（SD のルート）

末尾に、1 行 1 サンプルで並びます:

```
<millis> net-sta-before   free=... max=... min=...
<millis> net-sta-mode     free=... max=... min=...
<millis> net-scan-start   free=... max=... min=...   ← ★ ここが肝
<millis> net-join-before  free=... max=... min=...
```

★ **`net-scan-start` の `max`（最大連続ブロック）を見てください。**

| | 読み |
|---|---|
| `max` が数万あるのに落ちた | **ヒープではない** → (B) の線が濃い |
| `max` が小さい / `net-scan-start` の行が**出ていない** | **(A)** の線。行が無ければ**スキャンの途中で落ちた**ということ |

ホットスポット（手2）の `net-ap-*` と並べると、**station だけで何が減るか**が見えます。

## ★ 見つかった場合の回避案（原因が決まってから）

| 原因 | 案 |
|---|---|
| **(A) ヒープ** | ①ネットワークに入る前に本を閉じる（索引とページ配列を解放）②入る前に `clearOverflow()`（グリフ 128 スロットを返す。**散った小ブロックが最大の断片化源**）③スキャン結果に件数上限 |
| **(B) 電源** | ①USB 給電時のみネットワークを許す ②スキャンのチャンネル数を絞る ③送信出力を落とす |
| **(C) WDT** | 固まっている箇所を特定する。(A)(B) とは別の調査 |

★ **(A) と (B) で案がまったく違う**ので、先に区別する必要があります ── だから今回は計器だけを載せました。
