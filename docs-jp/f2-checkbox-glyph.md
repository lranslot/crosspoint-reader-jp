**版数**: v0.1
**作成日**: 2026-10-26
**位置づけ**: 仕様書 §7.5 の「F-2 段階2 (`☐` / `☑` への記号化)」の詳細設計
**状態**: **着手前。コードは 1 行も書いていない。**

---

## 0. 何を変えるのか

**`- [ ] ` という前置きを表示から消し、既存のカーソル欄に箱を描く。**

```
現状:
  ┌────────────────────────────────┐
  │ > - [ ] 牛乳を買う               │
  │   - [x] 卵を買う                 │
  └────────────────────────────────┘

変更後:
  ┌────────────────────────────────┐
  │ ■ 牛乳を買う                     │   ← 選択中 (反転)
  │ ☑ 卵を買う                       │
  └────────────────────────────────┘
```

**カーソル `"> "` は廃止し、箱がその役を兼ねる。**

---

## 1. なぜ字形 (`☐` U+2610) を使わないのか

**`UDEVGothic` には収録されている** (2026-10-26 に `.cpfont` を実測。
`☐` / `☑` / `☒` とも advance 17.125 px @10pt。仕様書 §3.6)。

**それでも自前描画を採る。**

| # | 理由 |
|---|---|
| 1 | **フォント非依存。**別のフォントを入れたユーザーで崩れない。`▶` を諦めて `>` にしたときと同じ論理 (仕様書 §6.3) |
| 2 | **advance が 17.125 px で、欄の 16.5625 px に収まらない。**字形を使うと欄を広げることになり、`viewportWidth` が変わって `CACHE_VERSION` の繰り上げが増える |
| 3 | **未収録フォント用のフォールバックが要らない。**経路が 1 本で済み、テストが倍にならない (F-5 §3.2 と同じ判断) |
| 4 | **矩形と線 2 本で足りる。**`drawRect` も `drawLine` も既にある |

---

## 2. ⚠️ `markPad` ではなく `markerWidth` の欄に載せる

**この 2 つは別物である** (仕様書 §8.7-8 に誤解の記録あり)。

| | 正体 | 値 |
|---|---|---|
| **`markerWidth`** | **カーソル欄の予約。**`viewportWidth` から引く | **16.5625 px** (`advance(">") + advance(" ")` = 11.75 + 4.8125) |
| `markPad` | **`findWrapOffset` の `extraWidth`。**「`[ ]` を `x` の幅で測る」ための測定の補正 | 数 px (符号つき) |

**箱を載せるのは `markerWidth` の欄。**欄の幅は変えないので
`viewportWidth` も変わらない。

---

## 3. 箱の寸法と 4 状態

### 寸法

| 項目 | 値 | 根拠 |
|---|---|---|
| 欄の幅 | **16 px** (`markerWidth` 16.5625 の整数部) | §2 |
| 行の高さ | **20 px** (`UDEVGothic_10` の `ascender`) | 仕様書 §3.6 |
| **箱の一辺** | **12 px** | 下記 |
| 左余白 | **2 px** (欄の左端から) | `(16 − 12) / 2` |
| 上余白 | **4 px** (行の上端から) | `(20 − 12) / 2` |
| 右の残り | 2 px | — |

**一辺 12 px を採る理由**: 14 px だと左右の余白が 1 px ずつしかなく、
**本文の 1 文字目と接して見える。**11 px は偶数でないためチェックの対角線が
中心からずれる。**12 px は余白 2 px が左右対称に取れ、偶数なので対角線が綺麗に出る。**

### 選択中は「反転」にする理由

| # | 理由 |
|---|---|
| 1 | **16 px の箱で 1 px と 2 px の枠の違いは e-ink では見分けられない** |
| 2 | **既存の UI が反転を選択の表現に使っている** (設定画面のタブ行。選択中のタブが黒地に白) |

### 描画の手順

| 状態 | 呼び出し |
|---|---|
| ① | `drawRect(x, y, 12, 12)` … 1 回 |
| ② | `drawRect` + `drawLine` × 2 (左下がりの短い線 + 右上がりの長い線) … 3 回 |
| ③ | `fillRect(x, y, 12, 12, black)` + `fillRect(x+2, y+2, 8, 8, white)` … 2 回 |
| ④ | ③ の後に `drawLine` × 2 を**白で** … 4 回 |

**すべて既存の API で足りる。**`fillRect` / `drawRect` / `drawLine` は
`GfxRenderer` にある。

> **⚠️ 線の太さは 1 px。**`drawLine` は 1 px 固定。チェックを太くしたい場合は
> 隣接する線をもう 1 本引く (実機で見てから判断する)。

## 4. 影響範囲 — **オフセット系は 1 つも壊れない**

**TXT リーダーには検索もしおりも無い** (`grep` で 0 件)。
文字列長に依存するのは次の 3 つだけで、**いずれもソースのバイト位置**である:

| 処理 | 依存先 | 影響 |
|---|---|---|
| `markOffset` | `offset + pos + markPos` — **ソースのバイト位置** | **なし。**表示用の文字列を変えても動かない |
| `nextOffset` | `offset + pos` — 同上 | **なし** |
| 進捗 (`currentOffset`) | ページ先頭のバイト位置 | **なし** |

**`outLines` は表示専用で、どこにも保存されない。**

## 5. ★ C5 (`- [ ]` が単独で 1 行を占める) が同時に消える

### C5 の正体

**`findWrapOffset()` の `preferSpace = true`。**

`- [ ] ` の**直後に半角スペースがある**ため、折り返しが必要になったとき
「収まる最後の空白」としてそこが選ばれる。日本語の本文には空白が無いので、
**行内の空白はそこ 1 つだけ**になる。

```
実機のスクリーンショットで確認 (2026-10-26):
  > -  [  ]
    あいうえおかきくけこさしすせそたち
    つてとなにぬねのはひふへほまみむめ
    もやゆよ
```

**1 行が丸ごと無駄になる。**

### なぜ消えるか

**前置きを `outLines` から取り除くと、行内の空白が消える。**
`lastFittingSpace` が 0 のままになり、`lastFittingOffset` (文字境界) に落ちる。

**→ C5 の単独修正は不要になる。**

## 6. 消える仕組み

**前置きを描かなくなれば「`[ ]` を `x` の幅で測る」必要が消える。**

| 消えるもの | 場所 |
|---|---|
| `markPad` / `markPadFor()` | `TxtReaderActivity.{h,cpp}` |
| `checkboxMarkPadSpace` / `checkboxMarkPadUpper` | 同上 |
| `findWrapOffset` の `extraWidth` 引数の利用 | 同上 (引数自体は残す) |

**仕様書 §8.1 の罠 2〜4 (幅の正規化 / `[X]` の負の補正 / `x` を基準にする理由) も
同時に消える。**

> **⚠️ §8.1 の罠は削除せず「解消済み」として残すこと。**
> なぜその対策が必要だったかの記録は、同じ問題を別の形で踏まないために要る。
