## 0. 何を変えるのか

**`- [ ] ` という前置きを表示から消し、既存のカーソル欄に箱を描く。**

```
現状:
  ┌────────────────────────────────┐
  │ > - [ ] 牛乳を買う               │
  │   - [x] 卵を買う                 │
  └────────────────────────────────┘

変更後:
  ┌────────────────────────────────┐
  │ ■ 牛乳を買う                     │   ← 選択中 (反転)
  │ ☑ 卵を買う                       │
  └────────────────────────────────┘
```

**カーソル `"> "` は廃止し、箱がその役を兼ねる。**

---

## 1. なぜ字形 (`☐` U+2610) を使わないのか

**`UDEVGothic` には収録されている** (2026-10-26 に `.cpfont` を実測。
`☐` / `☑` / `☒` とも advance 17.125 px @10pt。仕様書 §3.6)。

**それでも自前描画を採る。**

| # | 理由 |
|---|---|
| 1 | **フォント非依存。**別のフォントを入れたユーザーで崩れない。`▶` を諦めて `>` にしたときと同じ論理 (仕様書 §6.3) |
| 2 | ~~**advance が欄に収まらない**~~ **この理由は誤りだった (2026-10-26 訂正)。**10 pt の数字 (advance 17.125 > 欄 16.5625) だけを見て立てた理由だが、**欄の幅は本文フォントで変わる。**実測した 12 pt では欄 25 px に対し `☐` は約 20.6 px で**収まる。**字形を退ける理由にはならない |
| 2' | **大きさを選べない。**字形は本文フォントの大きさに縛られるが、自前描画なら `min(markerWidth-4, lineHeight-8)` で**欄いっぱいまで広げられる。**12 pt では 21 px 対 20.6 px でほぼ同じだが、線幅を一辺に追従させられるのは自前描画だけ |
| 3 | **未収録フォント用のフォールバックが要らない。**経路が 1 本で済み、テストが倍にならない (F-5 §3.2 と同じ判断) |
| 4 | **矩形と線 2 本で足りる。**`drawRect` も `drawLine` も既にある |

---

## 2. ⚠️ `markPad` ではなく `markerWidth` の欄に載せる

**この 2 つは別物である** (仕様書 §8.7-8 に誤解の記録あり)。

| | 正体 | 値 |
|---|---|---|
| **`markerWidth`** | **箱の欄の予約。**`viewportWidth` から引く | **`advance("> ")`。12 pt で 25 px** (§3) |
| `markPad` | **`findWrapOffset` の `extraWidth`。**「`[ ]` を `x` の幅で測る」ための測定の補正 | 数 px (符号つき) |

**箱を載せるのは `markerWidth` の欄。**欄の幅は変えないので
`viewportWidth` も変わらない。

## 3. 箱の寸法と 4 状態

### 寸法は固定値ではなく式

**本文フォントのサイズで全部変わる。**固定値を書くと必ず古くなるので式で持つ。

| 項目 | 式 | **12 pt (SD の UDEVGothic) での実例** |
|---|---|---|
| 欄の幅 | `markerWidth = getTextAdvanceX(cachedFontId, "> ")` | **25 px** |
| 行の高さ | `lineHeight = getLineHeight(cachedFontId)` (= `advanceY`) | **29 px** |
| **箱の一辺** | **`min(markerWidth - 4, lineHeight - 8)`** | **21 px** |
| 左余白 | `(markerWidth - 一辺) / 2` | 2 px |
| 上余白 | `(lineHeight - 一辺) / 2` | 4 px |
| **線幅** | **`max(2, 一辺 / 6)`** | **3 px** |

> **12 pt の 25 / 29 px は実測値である** (2026-10-26、`f2-test.md` の
> スクリーンショットから `scripts/checkbox_mockup.py` で計測)。
> **組み込み本文フォントのどの pt にもこの組み合わせは無い** (12pt は 21/34、
> 14pt は 24/40、16pt は 27-28/45、18pt は 31/51)。
> **つまりこの本は SD フォント経路で描かれている。**

#### 上限を置かない理由

初版は `CHECKBOX_SIDE = 12` で頭打ちにしていた。**これが「チェックが細い」の
正体だった** — 12 pt では欄も行も 21 px まで許しているのに、上限だけが効いて
内側が 10 x 10 しか残らず、2 本の斜線では墨が足りなかった。

**本文の ascender を超える pt は無い**ので、上限は要らない:

| 経路 | pt | 一辺 | 本文 ascender |
|---|---|---|---|
| 組み込み | 12 / 14 / 16 / 18 | 17 / 20 / 23-24 / 27 | 27 / 32 / 36 / 41 |
| SD (UDEVGothic) | 12 | **21** | 超えない |

> **SD フォントの 8 / 10 / 14 / 16 / 18 pt は未計測。**`markerWidth` は
> em 表から 17 / 21 / 29 / 33 / 38 px と出せるが (半角 = em/2、`"> "` = em)、
> `advanceY` は em との比が font 固有なので 12 pt の 1 点しか根拠が無い。
> **カードを挿して `.cpfont` のヘッダを読めば確定する。**

#### 線幅を一辺に追従させる理由

`GfxRenderer::drawLine(x1, y1, x2, y2, lineWidth, state)` は
**下方向にずらして太らせるだけ** (`drawLine(x1, y1 + i, ...)`)。45 度の線では
見かけの太さが `lineWidth` の約 0.71 倍になる。

`max(2, 一辺 / 6)` なら、見かけの太さ / 内側の幅が一辺 11〜34 px の全域で
0.11〜0.16 に収まる。**2 px 固定にすると一辺 34 px (18 pt) で髪の毛のように
なる** (比 0.04)。

> **下にしか伸びないので、素の線の終点を `stroke - 1` px 上げる。**
> そうすると太らせた帯の下端が内側の最終行にちょうど載り、枠にはみ出さない。
> クリップ処理が要らなくなる。

### ★ 2 つの軸を混ぜない — 箱の形は 4 状態すべて同一

**「選択されているか」と「チェックされているか」は別の軸である。**
箱そのものの形で選択を表すと、**塗りつぶした黒い箱が「チェック済み」と
読まれて 2 つの軸が混ざる。**

**→ 箱は 4 状態すべて同じ形 (一辺 12 px / 枠 1 px)。
選択は「欄の背景を反転する」ことだけで表す。**

| 状態 | 背景 (16 × 20 px) | 箱 | チェック |
|---|---|---|---|
| ① 未選択・未チェック | 白 | **黒** | — |
| ② 未選択・チェック済 | 白 | **黒** | **黒** |
| ③ 選択中・未チェック | **黒** | **白** | — |
| ④ 選択中・チェック済 | **黒** | **白** | **白** |

**形は変わらず、色だけが反転する。**どちらの軸も独立して読める。

### ★ チェックの形は B (x 印) — 候補 4 つの比較記録 (2026-10-26 決定)

実機のスクリーンショットから本文を借りて、欄だけを描き替えた見本を
`scripts/checkbox_mockup.py` で生成し、**等倍で本文の隣に並べて**判断した。
**箱だけを見ると分かった気になるが、本文の隣にあるときに見分けられるかが
問題だった。**

| 候補 | 形 | 判定 |
|---|---|---|
| A | 線幅 2 px の ✓ | **不採用。**墨が下半分に偏り、四隅が空く |
| **B** | **線幅 2 px 以上の x 印** | **採用** |
| C | 箱の内側を塗りつぶす | **不採用** |
| D | C の変種。反転時だけ内側に 1 px の隙間 | **不採用** |

**B を採る理由**

| # | 理由 |
|---|---|
| 1 | **左右対称なので、反転しても形が変わらない** |
| 2 | **内側の四隅まで墨が届く。**A は下半分だけで、小さい箱だと薄く見える |
| 3 | **4 状態がすべて別の形になる** |

**C を採らない理由**: ② (未選択・チェック済) が黒い四角、③ (選択中・未チェック)
が黒い欄になり、**一覧を目で流したとき「チェック済み」と「カーソル位置」が
どちらも黒い塊として競合する。**大きさは倍以上違うが、競合させる理由が無い。

**D を採らない理由**: ④ が「白枠 + 黒い環 + 白い中身」になり、③ の
「白枠 + 黒い中身」と**よく似てしまう。**隙間を入れると ④ が ③ に近づくので、
見分けを良くするつもりが逆効果だった。**8 倍で並べて確認済み。**

### 見本の作り方

```
python scripts/checkbox_mockup.py <screenshot.bmp|.png> <出力先> [--side N] [--stroke N]
```

`docs-jp/mockups/` に 12 pt (一辺 21 px / 線幅 3 px) の等倍と 8 倍がある。
**スクリプトは `drawLine` の太らせ方までファームと同じ算法で描く** —
ここが違うと見本とファームが別の絵になる (初版はこれを踏んだ)。

欄の寸法はスクリーンショットから自動実測する。**カードが無くても、
`bmp_to_png.py` が出した PNG を食わせれば作り直せる。**

### 4 状態

| 状態 | 欄の背景 | 箱 | x 印 |
|---|---|---|---|
| ① 未選択・未チェック | 白 | **黒** | — |
| ② 未選択・チェック済 | 白 | **黒** | **黒** |
| ③ 選択中・未チェック | **黒** | **白** | — |
| ④ 選択中・チェック済 | **黒** | **白** | **白** |

**③④ は①②の白黒を欄ごと 1 px 単位で入れ替えたもの。**
箱の形・位置・太さは 4 状態すべて同一で、変わるのは色だけ。

### 選択を「背景の反転」で表す理由

| # | 理由 |
|---|---|
| 1 | **箱の形が変わらないので、選択とチェックの 2 軸が絶対に混ざらない** |
| 2 | **12 px の箱では 1 px と 2 px の枠の差が e-ink で見分けられない** |
| 3 | **既存の UI がこの言語を使っている** (設定画面のタブ行。選択中のタブが黒地に白) |

### 描画の手順

| 状態 | 呼び出し |
|---|---|
| ① | `drawRect(箱, black)` ... 1 回 |
| ② | `drawRect(箱, black)` + `drawLine(..., stroke, black)` x 2 ... 3 回 |
| ③ | **`fillRect(欄, black)`** + `drawRect(箱, white)` ... 2 回 |
| ④ | ③ + `drawLine(..., stroke, white)` x 2 ... 4 回 |

**すべて既存の API で足りる。**`fillRect` / `drawRect` / `drawLine` は
`GfxRenderer` にあり、いずれも色と線幅を指定できる。

## 4. 影響範囲 — **オフセット系は 1 つも壊れない**

**TXT リーダーには検索もしおりも無い** (`grep` で 0 件)。
文字列長に依存するのは次の 3 つだけで、**いずれもソースのバイト位置**である:

| 処理 | 依存先 | 影響 |
|---|---|---|
| `markOffset` | `offset + pos + markPos` — **ソースのバイト位置** | **なし。**表示用の文字列を変えても動かない |
| `nextOffset` | `offset + pos` — 同上 | **なし** |
| 進捗 (`currentOffset`) | ページ先頭のバイト位置 | **なし** |

**`outLines` は表示専用で、どこにも保存されない。**

## 5. ★ C5 (`- [ ]` が単独で 1 行を占める) が同時に消える

### C5 の正体

**`findWrapOffset()` の `preferSpace = true`。**

`- [ ] ` の**直後に半角スペースがある**ため、折り返しが必要になったとき
「収まる最後の空白」としてそこが選ばれる。日本語の本文には空白が無いので、
**行内の空白はそこ 1 つだけ**になる。

```
実機のスクリーンショットで確認 (2026-10-26):
  > -  [  ]
    あいうえおかきくけこさしすせそたち
    つてとなにぬねのはひふへほまみむめ
    もやゆよ
```

**1 行が丸ごと無駄になる。**

### なぜ消えるか

**前置きを `outLines` から取り除くと、行内の空白が消える。**
`lastFittingSpace` が 0 のままになり、`lastFittingOffset` (文字境界) に落ちる。

**→ C5 の単独修正は不要になる。**

**前置きを描かなくなれば「`[ ]` を `x` の幅で測る」必要が消える。**

| `markPad` / `markPadFor()` | `TxtReaderActivity.{h,cpp}` |
| `checkboxMarkPadSpace` / `checkboxMarkPadUpper` | 同上 |
| `findWrapOffset` の `extraWidth` 引数の利用 | 同上 (引数自体は残す) |

**仕様書 §8.1 の罠 2〜4 (幅の正規化 / `[X]` の負の補正 / `x` を基準にする理由) も
同時に消える。**

> **⚠️ §8.1 の罠は削除せず「解消済み」として残すこと。**
> なぜその対策が必要だったかの記録は、同じ問題を別の形で踏まないために要る。

## 8. 未調査だったもの (実装で潰した / 残った)

| # | 内容 | 結果 |
|---|---|---|
| 1 | **箱を描く y 座標の基準** | **解決。**`renderPage()` のループが持つ `y` は行の上端で、`drawText` の `y` と同じ基準。欄は `y` 〜 `y + lineHeight` |
| 2 | **チェックの対角線の見た目** — 12 px で 1 px の線が e-ink で見えるか | **実機で「細くて見にくい」と判定された (2026-10-26)。**原因は上限 12 px (§3)。**上限を外して一辺を 21 px にし、形を x 印に、線幅を `max(2, 一辺/6)` にした。**再検証待ち |
| 3 | 前置きの長さの揺れ — `-` / `*` / `+`、インデント、`[X]` 大文字 | **解決。**`prefixLen = markPos + 2`、続く半角スペース 1 個も読み飛ばす。3 状態はいずれも 6 B で、どれも**測られない**ので折り返しは状態に依存しない |

### 実装で分かった追加の点

| # | 内容 |
|---|---|
| 1 | **箱の描画は prewarm のスキャン走査では行わない。**`renderLines()` に `drawBoxes` を足した。`drawText` はスキャン走査では文字を集めるだけだが、`fillRect` / `drawRect` は文字ではないので実際に描かれてしまう |
| 2 | **箱は `if (!line.empty())` の外で描く。**`- [ ]` の後ろに本文が無い行は空の視覚行になるが、箱は要る |
| 3 | **箱の一辺は欄と行高から決める** (`min(12, markerWidth - 4, lineHeight - 8)`)。本文フォントを大きくすると欄も広がるので、12 px 固定にすると余白だけが増える |
