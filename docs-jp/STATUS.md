### ★ 初めて現れた実害のある衝突 — #4174（行間の百分率化）

`072b6fc7 feat: line spacing as a percentage of font size`（2026-10-28）が
`CrossPointSettings::LINE_COMPRESSION` を書き換えた。

| | ベース | 上流 |
|---|---|---|
| 値 | `TIGHT / NORMAL / WIDE / EXTRA_WIDE`（4） | `LINE_SPACING_100 … _175`（**7**） |
| 既定 | `NORMAL`（1） | **`LINE_SPACING_120`（3）** |
| 意味 | 段階の名前 | **フォントサイズに対する百分率** |

**縦書きの列の送りはこの enum を流用している**（設計メモ §2.2）。

```cpp
static constexpr int COLUMN_RATIO_PERCENT[] = {115, 130, 150};  // TIGHT/NORMAL/WIDE
```

追随すると 3 つ同時に壊れる。

1. **コンパイルが通らない** — `TIGHT` / `NORMAL` / `WIDE` が消えている
2. **配列の範囲外読み** — `lineSpacing` が 3〜6 を取るようになるが要素は 3 つ
3. **既存設定の読み替え** — 既定が 1 から 3 に動くので、
   `settings.json` の値の意味が変わる。**索引キャッシュの検証項目にも入っている**ため
   全書籍の索引が作り直される

> **これは警告として予想していた事象そのものである。**前回「② #3528 字間・語間の設定
> … 縦書きにも通す必要が出る」と書いた。**その予想が現実の形で来た。**
> いま追随しないので実害は無いが、**追随するなら最初に手当てする 1 件目はこれ。**

## 再開の手順

```powershell
$env:PYTHONUTF8 = "1"

cd D:\dev\crosspoint-reader-jp
git fetch upstream --prune
git status
git log --oneline -5
git log --oneline 81028d58..upstream/develop    # 上流の進み具合（追随はしない）
```

**ビルド前に `$env:PYTHONUTF8 = "1"` が必須。**

**`.md` は読み物ではなく TODO の道具。**組版まわりの機能 (縦書き・ルビ・
禁則・傍点) は `.md` に適用しない。チェックボックスは `.md` のみ
(仕様書 §6.3「`.md` の位置づけ」)。

**端末で読む前提の文書 (`docs-jp/tests/` 配下) では、表・コードフェンス・
見出し記法を使わない。箇条書きの `- [ ]` は絶対に書かない。**
リーダーが解釈する Markdown は**チェックボックスだけ**で、他は生のまま出る。
`- [ ]` と書くと端末では本物のチェックボックスになる (仕様書 §6.3 / §8.7-10)。

**実機の見た目を確かめるときは写真ではなくスクリーンショット。**
POWER + DOWN で全画面から撮れる（設定画面でも可）。`/screenshots/` に
480×800 / 1bpp の BMP が出るので、PNG にして 1 px 単位で見る:

```powershell
python scripts/bmp_to_png.py G:/screenshots <出力先>
```


### 実機の作法

- **USB がロックされているので、書き込みは SD カード経由のみ。**
  `firmware.bin` を SD ルートに `update.bin` としてコピー → 起動 → **後で削除**
- **`settings.json` と `wifi.json` は絶対に消さない**
- **シリアル出力が無い。**診断は SD のファイルか画面に出す
- OTA と SD カード更新の機能を削除してはならない
