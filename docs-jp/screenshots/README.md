# 実機スクリーンショットの基準

**端末から取った画像は再生成できない。焼き直したら同じものは二度と撮れない。**
ここにあるのは**比較の基準として意味のあるものだけ**である
(仕様書 §8.7-7)。

撮り方: **POWER + DOWN** を同時押し。全画面から撮れる。
`/screenshots/` に 480x800 / 1bpp の BMP が出る。PNG への変換:

```
python scripts/bmp_to_png.py G:/screenshots <出力先>
```

**増やすときは、何の基準なのかをこの表に 1 行足してから置くこと。**
説明の無い画像は、半年後には区別が付かない。

## ★ 完了条件⑧

**縦書きを入れた後、横書きがこれと 1 px も変わらないこと。**

`saishu_sensoron_p2_1pct_52813.png` が本命の比較対象である。
縦書きは新しい経路を足すのであって、**横書きの経路を 1 行も変えてはならない。**
変わっていたら、それは縦書きの実装が横書きに染み出している。

比べ方: 焼いた後に同じページを撮り、PNG に変換して**バイト列を比較する。**
目視ではなく `cmp` で見ること。

```
python scripts/bmp_to_png.py G:/screenshots <出力先>
cmp <出力先>/saishu_sensoron_p2_*.png docs-jp/screenshots/saishu_sensoron_p2_1pct_52813.png
```

> **⚠️ ページ番号と進捗率がファイル名に入る。**同じページを撮っても
> 通し番号は変わるので、名前ではなく `p2_1pct` の部分で照合すること。

## ⚠️ 足りていない基準

| # | 欲しいもの | なぜ |
|---|---|---|
| 1 | **ASCII・数字・半角カナが本文に出てくるページ** | 段階1 の「ASCII も 1 マスを占めて正立する」の判定に要る。**青空文庫は数字も漢数字** (「十五年」「六四頁」) なので実作品からは取れない。**`docs-jp/tests/f5-ascii-test.txt` を自前で作った。**まだ実機に入れていない |
| 2 | **4 方向の向き** | 縦書きは向きごとに `columnsPerPage` と `charsPerColumn` が両方変わる (`f5-vertical-writing.md` §12.2)。いまは縦持ちしか無い |

## 命名について

**端末が付けたファイル名をそのまま使う。**
`<書名>_p<ページ>_<進捗>pct_<通し番号>.png` で、**ページ番号と進捗率が
そのまま入っている**ため、どの画面かを後から特定できる。
意味のある名前に変えると、次に撮った画像と見分けが付かなくなる。
