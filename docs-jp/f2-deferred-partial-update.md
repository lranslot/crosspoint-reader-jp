## 0. 何を保留したのか

**2つで1組の話。**片方だけでは効かない。

| # | 内容 | 効果 |
|---|---|---|
| **A** | **窓更新** — 変化した矩形だけをパネルに転送する | E-Ink 転送 548ms を1行分に縮める |
| **B** | **固定描画** — トグル時に `loadPageAtOffset()` を呼ばず、`currentPageLines` を使い回す | 折り返し計算 233ms を消す |

**A だけだと**、転送を縮めても計算 233ms + prewarm 269ms が残り、頭打ちになる。
**B だけだと**、1591ms → 約940ms 止まり。支配項の 548ms が残るので体感が変わらない。

**両方入れて初めて「一瞬で切り替わる」に届く。**

## 3. ⚠️ 罠1: グレースケール中は逆に遅くなる

```cpp
// Ssd1677Driver.cpp:497-504
if (_inGrayscaleMode) {
  displayImpl(bus, fb, nullptr, RefreshMode::Half, turnOff, /*async=*/false);
  return;   // 窓ではなく全画面 HALF リフレッシュ
}
```

`HALF_REFRESH` は **1720ms** (`HalDisplay.h:16`)。

AA が有効だとページ描画の最後が `displayGrayBuffer()` なので、パネルは常にグレースケール状態。
**そこで窓更新を呼ぶと、現状 (1591ms) より遅くなる。**

同様に、ダークモード (`_inverted || _inversionDirty`) でも
`displayBuffer(FAST_REFRESH)` に落ちる (`FreeInkDisplay.cpp:757-763`)。

### 対策と、そこから出る論点

**`.md` を開いている間は AA を切る。**パネルがグレースケールに入らなくなる。

> **煮詰めるべき点**: これは「`.md` の本文が AA なしになる」ことを意味する。
> チェックリストなら気にならないはずだが、`.md` で長文を読む場合はどうか。
> **ファイル種別で切るのか、チェックボックスの有無で切るのか、設定にするのか。**

## 4. ⚠️ 罠2: 差分の基準が更新されない

通常経路 (`FreeInkDisplay.cpp:680-686`) は表示後に `swapBuffers()` を呼び、
`frameBufferActive` を「直前に表示したフレーム」として保つ。
**`displayWindow` はこれを呼ばない。**

ドライバ側も、`prev != nullptr` の経路ではリフレッシュ後の RED 再シードをしない
(`Ssd1677Driver.cpp:545-549` は `prev == nullptr` のときだけ再シードする)。

結果、次の全画面 FAST リフレッシュは**トグルした文字の位置だけ古い基準と差分を取る。**

理屈の上では「既に正しいピクセルをもう一度駆動する」だけで無害なはずだが、
**残像として出るとすればここ。コードを読んで確定できる種類の話ではない。**

> **煮詰めるべき点**: SDK に手を入れずに回避できるか。
> フォーク側で窓更新の直後に基準を明示 seed する手はあるか
> (`FreeInkDisplay` に `syncRedRamFromFrameBuffer()` 相当が見えている。要確認)。
> SDK 側のバグとして上流 (Free-Ink) に報告すべき筋の話かもしれない。

## 5. B (固定描画) を単独でやらない理由

**書き込みの検証が消えるため。**

現状 `render()` は毎回 `loadPageAtOffset()` でファイルを読み直す (`TxtReaderActivity.cpp:336-339`)。
つまり**画面に出た `[x]` は「ファイルにそう書かれている」ことの証明**になっている。

固定描画にすると、メモリ上の文字列を書き換えて表示するだけになるので、
**書き込みが失敗しても成功したように見える経路が生まれる。**

F-2 の初回実装ではこの検証を優先する。**A と同時に入れるのが正しい順序。**

### 副産物: 折り返しリスクが消える

`f2-checkbox-investigation.md` §4 で指摘した「`advance('x') > advance(' ')` だと
1行増えてページ境界の文字が消える」問題は、**固定描画にすればトグルの瞬間には起きない。**

ただし**ページを離れて戻ると `loadPageAtOffset` が走って再現する。**
根治するには計測時だけ `[x]` → `[ ]` に正規化する必要がある。

> **煮詰めるべき点**: 正規化まで入れるか、`advance(' ') == advance('x')` を
> 実機で確認して「等幅フォント前提」と割り切るか。

## 8. 煮詰めるべき論点 (再掲)

| # | 論点 |
|---|---|
| 1 | AA を切る範囲。ファイル種別 / チェックボックスの有無 / 設定項目 |
| 2 | 罠2 の残像を、SDK に触れずに回避できるか。上流報告の要否 |
| 3 | 折り返しの正規化まで入れるか、等幅前提で割り切るか |
| 4 | カーソル移動で2行が変わる。窓を2回呼ぶか、両方を含む1つの矩形にするか |
| 5 | この改修は TXT 以外 (EPUB / XTC / UI) にも効く。**F-2 専用にせず `GfxRenderer` の公開機能として作るか** |

> **論点5 が一番大きい。**`GfxRenderer::displayWindow` として通せば、
> リーダー全体・UI 全体の応答性に効く。上流に PR を出す価値もある
> (`GfxRenderer.h:181` の宣言がコメントアウトされたまま残っているのは、
> 上流も「いつかやる」と思っている証拠)。
